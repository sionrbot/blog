# Domain docs

This repository uses a single-context domain layout:

- `GLOSSARY.md` at the repository root defines domain vocabulary.
- `docs/adr/` holds architectural decision records.

## Before exploring

Read `GLOSSARY.md` and any ADRs relevant to the area being explored.

If these files or directories do not exist, proceed silently.
The domain-modeling skill creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
Respect any distinctions and avoided synonyms recorded in the glossary.

When a needed concept is absent, check whether existing terminology covers
it. Note genuine gaps for domain-modeling.

## Decisions

If a proposal contradicts an existing ADR, name the ADR and explain why
the decision should be reconsidered.
