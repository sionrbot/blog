# Search

The global search dialog searches published post titles, descriptions, tags, and rendered bodies.
Open it from the header on any page. Search stays over the current page; closing
the dialog restores the trigger's focus and the page's scroll position.
The former `/search/` and `/zh/search/` pages are removed, without compatibility
entries or redirects.
Search opens only from the header button; `/` is ordinary input, not a shortcut.
The input receives focus on opening. Close with Escape, the close button, or a
click on the backdrop; the current query and completed results remain available
when reopening on the same page. Arrow keys move between result links, and Enter
opens the focused result. These shortcuts do not interrupt Chinese composition.

Pagefind generates `dist/pagefind/` during Astro's `astro:build:done` hook, so the
existing build and deployment commands also produce and publish the search index.
Search runs in the reader's browser without a search service.

Each post is indexed once, from its unprefixed UI route. `PostLayout.astro` marks
that article with `data-search-post`; navigation, dates, and the back-to-blog link are
excluded. Drafts do not have production pages and cannot enter the index.
Metadata includes the original title, description, content language, post ID,
publication date, and tags. Result navigation uses the current UI language.
The search term belongs to the current dialog and is not stored in the URL.
Opening, searching and closing leave the page URL unchanged. Navigating or
switching UI language loads a new page with a closed, empty search dialog.

Both UI languages search the same index. The index uses Pagefind's `zh` tokenizer
to segment Chinese text and preserve English words. This deliberately disables
English stemming: related English word forms are not guaranteed to match.
The content's actual language remains in metadata and HTML; the index setting
does not translate or relabel the original content.

On the first nonempty query, the browser loads the Pagefind bundle under the deployment base and supplies that
base as `baseUrl`. This supports both the GitHub Pages repository subpath and a
root deployment. Index files are generated by production builds; use `vp run
build` followed by `vp run preview` to test search against current content.
The dev server also serves the last production index from `dist/pagefind/`.
Rebuild after changing content to refresh it; development drafts are not indexed.

Run `vp test --project build tests/build/search.test.ts` to verify Chinese and
English queries against the emitted JavaScript/WebAssembly, deduplication,
draft exclusion, metadata, and both deployment bases. These tests exercise the
real search runtime with file-backed transport and simulated HTML UI languages;
browser interaction tests cover opening and closing the dialog, focus, keyboard
navigation, Chinese input, result loading, and narrow-screen layouts. Build tests
also verify that the removed search pages are absent from output and the sitemap.

To run the browser tests against the development server and the repository base:

```sh
vp run build
SEARCH_TEST_BASE=/blog pnpm exec e2e run tests/e2e/deterministic/default/search.e2e.ts --target desktop
```

The direct E2E command starts the configured development server. To exercise a
root-hosted production build with the suite's desktop and narrow targets:

```sh
SITE_URL=https://fixture.example vp run build
SITE_URL=https://fixture.example pnpm run test:e2e -- tests/e2e/deterministic/default/search.e2e.ts
```

Keep `SEARCH_TEST_BASE` unset for the root-hosted run. Build again with the normal
site configuration before using the development server at the repository base.
