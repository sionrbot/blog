# i18n testing

Test the English (`en`, no URL prefix) and Simplified Chinese (`zh-Hans`, `/zh/`)
UI against [the language specification](../docs/i18n-spec.md). UI language follows
the URL; authored content retains its original text and language. Article lists,
details and tags share the `/articles/` route family, with `/zh/` selecting Chinese
UI. Old `/blog/<slug>/` and `/blog/tag/<tag>/` addresses, including their Chinese
variants, are removed and return HTTP 404 without redirects.
See [TESTING.md](TESTING.md) for shared setup, fixture lifecycle and reports.

## What to test

| Layer and source                                                                   | Contracts                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Static: `x18n.config.ts`, `tests/build/x18n-tooling.test.ts`                       | Dictionary/reference agreement; unknown and unused keys; absent/empty translations; placeholder mismatch detection; valid repeated placeholders; rejected writes preserve files                                                                     |
| Unit: `tests/unit/i18n.test.ts`                                                    | Registry/dictionary/tool language agreement; exact key sets; trimmed nonempty values; placeholders; default/unknown/special-value fallback; invalid defaults; literal interpolation and missing parameters; localized page identities and fragments |
| Unit: `tests/unit/dates.test.ts`                                                   | English/Chinese UTC dates, route alias, year boundaries and locale behavior across process timezones                                                                                                                                                |
| Build: `tests/build/i18n.test.ts`                                                  | Static UI text/attributes and page identity; article text/links/content language; forms; canonical/hreflang/sitemap/RSS consistency; explicit localized error pages                                                                                 |
| Build: `tests/build/schema.test.ts`                                                | Default content language, valid non-UI content languages and invalid language rejection with a corrected control                                                                                                                                    |
| Build: `tests/build/navigation-config.test.ts`, `page-math.test.ts`, `seo.test.ts` | Configured navigation and footer labels/destinations; shared-page translated titles/math styles; error-route filtering that retains legitimate 404-named content                                                                                    |
| Browser: `tests/e2e/deterministic/i18n/navigation.e2e.ts`                          | Bidirectional language switching, original content and anchors, tag/pagination identity, refresh, URL precedence, script-blocked navigation, dropdown open/dismiss behavior, focus/selected state and 360px layouts                                 |

Use mixed-language fixtures with enough posts to trigger pagination. Build once
and inspect both UI routes. Expected content and metadata must be independent of
production translation, formatting and sorting functions. Use structural selectors
and then assert text; an English accessible name alone cannot identify controls
in both languages.

Open the language dropdown before switching through its visible English or 简体中文
links. Check that it starts closed, marks the current language, opens with Enter
and Space, and closes on Escape (returning focus to the trigger) or an outside
click. Include the open dropdown when checking 360px layouts. Assert original text, links,
code and `lang` attributes against fixture expectations, not only against the
other rendering. Check translated Contact pages use their own canonical URLs;
shared original content uses the specification's preferred canonical and alternate
relationships. RSS includes each original once. System-generated article and tag links, search
results, canonical URLs and hreflang alternates use `/articles/`, never the legacy
route family.

`tests/build/base-path.test.ts` covers root hosting, the historical
`/sionrbot-blog` base and the GitHub Pages `/blog` base. The deployment base is
independent of the article route: `/blog/articles/<slug>/` is a canonical Pages
URL, while `/blog/blog/<slug>/` is removed. Assert that no legacy article or tag
HTML is emitted (including non-ASCII tags), real preview requests return 404
without `Location`, `Refresh` or a meta refresh, and corresponding `/articles/`
pages return 200. Legacy routes must not enter the sitemap, feed or search index.
Draft articles and draft-only tags must not produce public pages. Browser
navigation tests verify that removed English and Chinese article/tag addresses
remain on their requested URL without redirecting.

## Run the checks

After installing the pinned dependencies, run the shared checks in
[TESTING.md](TESTING.md#run-unit-and-build-tests). For focused language validation:

```sh
pnpm run i18n:check
pnpm run test:unit
pnpm run test:unit:tz
vp run build
vp test --project build tests/build/i18n.test.ts tests/build/x18n-tooling.test.ts
vp test --project build tests/build/navigation-config.test.ts tests/build/page-math.test.ts tests/build/schema.test.ts tests/build/seo.test.ts
pnpm run test:e2e -- --variant i18n --target desktop,narrow,webkit
```

Translation-tool probes run in temporary copies. Require the expected exit code,
diagnostic code and file contents, with valid controls; a crashed process does
not establish the intended diagnostic. Tests must leave real dictionaries and
pages unchanged.

## Scanner and browser boundaries

The usage scanner matches literal `t.key` references in Astro and TypeScript
source, excluding dictionary files. It is a text matcher: comments can count as
references; aliases, destructuring and dynamic keys need explicit scanner support.
Do not mark every key used to suppress diagnostics.

The custom placeholder plugin recognizes `{name}`. The tooling probe captures
the installed CLI's whitespace-only translation gap; dictionary unit tests enforce
`trim()` nonempty values. Key completeness does not establish translation quality
or browser behavior. The CLI's `--strict` gate is required because default warnings
need not fail, and MCP diagnostics do not replace the project command.

The automated script-independent browser case uses CSP to block page scripts;
it does not create a browser context with `javaScriptEnabled: false`. For that
additional manual check, disable JavaScript in the browser and verify direct
English/Chinese pages, original content and ordinary language links. Fragment
preservation depends on the page script; fragments are not sent to the server.

Check Chinese glyphs, wrapping and reading comfort in an actual browser at 360px.
These observations do not establish identical fallback fonts across platforms.
Explicit `/zh/404/` output and a hosting platform's response to an unknown `/zh/`
URL are separate contracts; verify the latter against the deployed host.

## Agent workflow

Use the project `x18n` skill for keys/translations, `x18n-check` for diagnostics and
`x18n-setup` for configuration. Their `.agents/skills/` entries link to the installed
package; install locked dependencies before using them and review upstream skill
changes with package upgrades.

Use the configured x18n MCP for interactive status/search/key inspection and
scoped writes; use CLI JSON as the fallback. `.codex/config.toml` launches
`pnpm exec x18n mcp` from this project. Restart the connection after configuration
changes. For manual administration, `pnpm exec x18n ui` opens the separate UI.

```sh
pnpm exec x18n doctor
pnpm exec x18n status --json
pnpm exec x18n check --strict --json
pnpm exec x18n prompt check
```

Inspect state and relevant keys before changing translations. Read rename/delete
plans before applying them. Preserve the project's property-based `t.key` convention.
Finish translation changes with `pnpm run i18n:check` and `pnpm run test:unit`, plus
the normal project checks and affected build/browser tests.
